Upgrade my existing Multi-User RAG application from V2.0 to V2.20.

Current Stack:

* Next.js frontend
* FastAPI backend
* Google OAuth login
* JWT authentication
* PostgreSQL for user/document metadata
* ChromaDB for vector storage
* RAG pipeline with document upload and question answering

Goals for V2.20:

1. Retrieval Quality

* Add a relevance threshold before generating answers.
* If retrieved chunks are below threshold, do NOT generate document-based answers.
* Return: "I could not find relevant information in the uploaded documents."
* Do NOT show citations when retrieval fails.

2. Intent Router

* Detect greetings and casual conversation.
* Greetings such as "hi", "hello", "how are you" should bypass RAG and receive normal conversational responses.
* Only use retrieval when the query appears document-related.

3. Chat History

* Store conversations in PostgreSQL.
* Create chats and messages tables.
* Use only recent messages (last 4-8) plus a running summary when sending context to the LLM.
* Do not send full chat history every request.

4. Streaming Responses(if my current llm groq allows this other wise tell me i will think to change)

* Implement token streaming from backend to frontend.
* Display answers progressively in the UI.
* Keep source citations attached after generation completes.

5. Source Citations

* Store document_id, filename, page number and chunk metadata.
* Display citations only when the answer uses retrieved context.
* Remove duplicate citations.
* Clicking a citation should open the corresponding PDF in a sidebar at the exact page.

6. Document Viewer

* Add PDF viewer sidebar.
* Clicking a citation automatically navigates to the cited page.
* Highlight the cited chunk if possible.

7. Hybrid Retrieval

* Keep existing vector similarity search.
* Add keyword search (BM25/PostgreSQL Full Text Search).
* Combine semantic score and keyword score.
* Return the best ranked chunks.

8. Retrieval Debugging

* Add developer/debug mode.
* Show:

  * Retrieved chunks
  * Similarity scores
  * Keyword scores
  * Final ranking score

9. Database Design

* Store only metadata in PostgreSQL.
* Store files in persistent storage.
* Store embeddings in ChromaDB.
* Avoid storing full PDFs inside PostgreSQL.

10. User Experience

* Loading indicators during retrieval.
* Streaming answer animation.
* Better empty-state messages.
* Graceful handling of irrelevant questions.

Expected Deliverables:

* Updated database schema
* Migration scripts
* Backend implementation
* Frontend implementation
* API changes
* Folder structure
* Detailed explanation of architectural decisions
* Production-ready code following best practices.
